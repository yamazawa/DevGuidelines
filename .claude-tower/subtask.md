# サブタスク: 未コミットだった管理塔運用ルールをガイドラインに反映するー①

masterの作業ツリーに未コミットで残っていた変更を、最新のmaster（#5のFB対応マージ後）に統合して反映する。
変更は元リポジトリのstash（`stash@{0}`、メッセージ「未コミットの管理塔運用ルール（Issue化のため退避）」）にも退避してある。
worktreeからも`git stash show -p stash@{0}`で参照できるが、`git stash pop/drop`は行わない（stashの削除は人間が確認後に行う）。
以下の内容を正とし、stashは差分確認の補助に使う。

## CommonGuideLine.md

- 見出し1行目を「# 共通ガイドライン」にする。
- 冒頭の説明文の後に「# Claude管理塔での管理」章を追加する（「ガイドラインへのFB」章より前）。
```
# Claude管理塔での管理

全プロジェクトはClaude管理塔（`yamazawa/ClaudeManagementTower`）で管理する前提とする。\
Issue・MRの作成、MRの実装実行、マージは管理塔から行う。

- 1タスクを1 Issue、1サブタスクを1 MRとする。
- MRは管理塔がworktree・ブランチ・Draft PRとして作成する。
- MRの説明文は`Related to #Issue番号`とし、`Closes #Issue番号`は使わない。
- マージ前のレビューNGは、同一MRで修正する。
- マージ後に発覚した問題は、新しいMRで対応する。
- Issueのクローズ・MRのマージは、人間が明示的に指示した場合のみ行う。
- `.claude-tower/`配下には管理塔が使うファイルを置く。

※管理塔が実行時に渡す指示と本ガイドラインが衝突する場合、管理塔の指示を優先する。
```
- 「# スプリント運用」章（Issue・ブランチ・MRの節を含む）を、以下の「# Issue・MRの命名」章に置き換える。
```
# Issue・MRの命名

Claude管理塔の命名規則に合わせる。\
スプリント番号・タスク番号はタイトルに付けない。

## Issue

タイトルは対応内容を表す日本語の文とする。\
アイデアマンの提案から作成したIssueは、管理塔が先頭に`[IdeaMan] `を付ける。

## MR

MR名は「Issue名ーMR固有名」とする（区切りは全角の「ー」）。\
MR固有名を省略した場合、管理塔が丸数字の連番（①②…）を割り当てる。\
MRはIssue内の機能単位で切る。

## ブランチ

ブランチ名は管理塔が作成時に付ける。

- 既存IssueへのMR : `issue-{Issue番号}-{MR固有名の英語スラッグ}-{連番}`
- IssueとMRの同時作成 : `issue-new-{一意な識別子}-subtask-1`

※MR固有名を英語スラッグにできない場合、スラッグは`subtask`になる。
```
- 「# 役割分担」の1項目目「Issue作成、MR作成、ブランチ作成、コーディング＋CommitはClaudeが行う。」を以下3項目に置き換える。
```
- Issue・MRの作成は、人間が管理塔の画面から、またはClaudeが管理塔ツールで行う。
- Claudeは`gh issue create`・`gh pr create`等でIssue・MRを直接作成しない。
- コーディング＋CommitはClaudeが行う。
```

※管理塔の自律実行では、これらの操作は管理塔側で拒否される。
